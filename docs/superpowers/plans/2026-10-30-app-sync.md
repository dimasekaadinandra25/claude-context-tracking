# Desktop App Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Claude Usage Monitor app sends every session's lifetime usage, bucketed by UTC hour and model, to `claude-usage-server` every 30 minutes and about 1 minute after startup. The server URL and API key are set in a settings panel.

**Architecture:**
- `Session` gains lifetime fields that `reset_baseline` never clears.
- A new `config.rs` holds settings plus the sync watermark.
- A new `sync.rs` builds chunked payloads and posts them with `ureq` on the existing watcher thread.
- The UI gets a gear button for settings and a sync status line, fed through the existing `Update` channel.

**Tech Stack:** Rust 2024, eframe/egui 0.37, serde/serde_json, `dirs`, new dependency `ureq` (blocking, rustls).

**Spec:** `docs/superpowers/specs/2026-10-30-usage-server-design.md`. Read the sections "How usage is counted", "What the app sends", "Ingest (API key)" and "Desktop app changes". The ingest endpoint is `POST {server_url}/usage/v1/sessions` with header `X-API-Key`.

## Global Constraints

- **No code comments of any kind.** `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` must be clean. `cargo test` must pass.
- One-line commit messages with no Co-Authored-By trailer. Commit only when the user asks.
- Each request carries ≤ 200 sessions **and** ≤ 20,000 hour rows in total. A chunk is cut early when the next session would exceed either limit.
- Only sessions whose lifetime growth (the sum of their hour rows' `new_context`) is > 0 are sent.
- The HTTP timeout is 15 s. There is no retry queue; the watermark makes the next tick resend.
- Hour key format is `YYYY-MM-DDTHH:00:00Z`, taken from the request timestamp's first 13 characters plus `:00:00Z`.
- Config files go in `dirs::config_dir()/claude-usage-monitor/`: `config.json` holds `{server_url, api_key}`, and `sync_state.json` holds `{watermark}`. The env vars `CLAUDE_USAGE_SERVER_URL` and `CLAUDE_USAGE_API_KEY` override `config.json`.
- The in-app New context column (growth since the app started) is unchanged.

## Review Focus

- **The first run backfills months of sessions:** chunks respect both limits, and the watermark advances only after every chunk succeeds. Test: `chunks_respect_session_and_hour_limits` (Task 2).
- **The server is down or rejects the key:** the watermark is unchanged and the status shows the reason. Test: `failed_send_keeps_watermark` (Task 2).
- **App restart:** the hourly buckets rebuilt from the transcripts equal the ones before the restart. Test: `reset_baseline_keeps_lifetime_hours` (Task 1).
- **`/model` and `/compact`:** the first request afterwards adds a request count but no growth. Test: `hours_follow_rebaseline_rules` (Task 1).
- **An empty URL or key:** nothing is sent, and the status reads "Sync off". Test: `sync_disabled_without_settings` (Task 2).

### Task 1: Lifetime hourly usage on `Session`

**Files:** Modify `src/session.rs` (struct, `record_request`, `record_compaction`, `reset_baseline`, tests).

**Interfaces:**
- Produces: `#[derive(Clone, Copy, Debug, Default, PartialEq)] pub struct HourUsage { pub new_context: u64, pub requests: u32 }`
- Produces: `Session.hours: BTreeMap<(String, String), HourUsage>` keyed by `(hour_key, model)`, and `Session.compactions_lifetime: u32`.
- Produces: `pub fn hour_key(at: &str) -> Option<String>`, and `Session::lifetime_new_context(&self) -> u64`, which sums `hours`.

`record_request` always does `requests += 1` in the bucket for `(hour_key(at), model)`. Growth goes into the same bucket under exactly the rules that already add to `new_context`. Every place that increments `compactions` also increments `compactions_lifetime`. `reset_baseline` leaves both new fields untouched.

### Task 2: Config, watermark, payload and sending

**Files:**
- Create `src/config.rs` and `src/sync.rs`.
- Modify `Cargo.toml` to add `ureq = { version = "3", default-features = false, features = ["rustls", "json"] }`, using the latest 3.x that compiles. Also add `serde` `Serialize`.
- Modify `src/main.rs` to add the modules.

**Interfaces:**
- `config.rs`:
  - `#[derive(Clone, Default, PartialEq, Serialize, Deserialize)] pub struct Config { pub server_url: String, pub api_key: String }`
  - `pub fn load() -> Config` merges the file and the env overrides; a missing or invalid file gives the default.
  - `pub fn save(&Config) -> io::Result<()>` writes atomically with the existing `export::write_atomic`.
  - `pub fn load_watermark() -> Option<String>` and `pub fn save_watermark(&str) -> io::Result<()>`.
  - `Config::is_enabled(&self) -> bool` is true when both fields are non-empty after trim.
- `sync.rs`:
  - `#[derive(Serialize)] struct Payload<'a> { machine: &'a str, app_version: &'static str, sessions: Vec<SessionPayload> }`
  - `SessionPayload` has exactly the JSON fields of the spec's ingest example:
    - `start_context` = `base_context`
    - `new_context` = `lifetime_new_context()`
    - `compactions` = `compactions_lifetime`
    - `title` = `name()`
    - `first_at` / `latest_at` as-is
    - `hours: Vec<HourPayload{hour, model, new_context, requests}>`
  - `pub fn chunks(sessions: &[Session], watermark: Option<&str>) -> Vec<Vec<&Session>>`: filters `latest_at >= watermark` and lifetime growth > 0, sorts by `latest_at` ascending, and cuts at 200 sessions or 20,000 hour rows. A single session over 20,000 rows goes alone in its chunk.
  - `pub enum SyncStatus { Off, Synced(SystemTime), Failed(String) }`
  - `pub struct Syncer { last_run: Option<Instant>, last_config: Config }` with `new()` and `tick(&mut self, sessions: &[Session], machine: &str) -> Option<SyncStatus>`.
    - It returns `Some` only when it ran.
    - It runs when 30 min have passed since the last run, or ≥ 60 s after startup on the first run, or right away when `config::load()` differs from `last_config`.
    - It posts each chunk with the `X-API-Key` header and a 15 s timeout.
    - Only if every chunk got a 2xx does it save the watermark as the max `latest_at` sent.
    - A non-2xx response gives `Failed("HTTP <code>: <body message>")`, and a transport error gives `Failed(<error>)`.
  - Split the network call behind `fn post(url: &str, key: &str, body: &str) -> Result<(), String>` so the tests can drive `Syncer::run_with(post_fn, ...)`, which takes the poster as a closure parameter.

### Task 3: Watcher wiring, settings panel, status line

**Files:** Modify `src/watcher.rs` (`Update::Sync(SyncStatus)`, calling `syncer.tick` next to `exporter.tick`), `src/app.rs` (a gear `info_button`-style icon in `top_bar`, a settings `egui::Window`, a status label), and `README.md` (a Sync section).

**Interfaces:**
- Consumes: `sync::Syncer`, `SyncStatus`, `config::{load, save, Config}`.
- Settings window:
  - A "Server URL" text field.
  - An "API key" field with `TextEdit::password(true)`.
  - A Save button, which calls `config::save`; the watcher picks up the change on its next 2 s poll.
- Status label in the top bar, weak text:
  - `Sync off`
  - `Synced HH:MM`, in local time; a UTC `HH:MM` is acceptable if local time needs a new dependency
  - `Sync failed: <reason>`, where the reason is truncated to 60 characters and the full text shows on hover.
